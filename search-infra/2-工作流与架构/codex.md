# Codex · 工作流与架构

> **一句话**：Codex 证明了"单个 agent"能走多远——真正的秘密是两层循环 + 一个能"中途压缩还不断片"的主循环 + 让模型写代码批量调工具。

## 背景

OpenAI 官方终端 agent，开源 Rust。分析基于 main 分支源码，主循环 2843 行代码全部读过。

## 两层循环（主循环的真实结构）

```
外层 run_turn（用户说一句话 = 一轮）
  └─ 内层 run_sampling_request（一次"模型思考+工具执行"批次）
       模型输出工具调用 → 并行执行 → 结果写回 → 继续
       直到：模型不调工具了 / token 到限 / 用户插话
```

关键机制：

- **用户插话不丢**：用户在 agent 干活中途发的消息进入排队区，下一圈循环开头就会被处理（steering 机制）。
- **Stop hook（强制续跑）**：模型想收工时，钩子先拦一道——钩子可以注入"你还没干完，继续"的提示词。这是"把循环到做完做成产品机制"（和 Trae SOLO 的 Ralph Loop 独立撞车）。

## Code Mode（模型写代码调工具，本产品最前沿的设计）

传统方式：模型调一次工具 → 结果进上下文 → 模型再调一次 → …（来回十次，上下文被中间结果塞满）。

Code Mode：模型直接写一段 JS，在 **V8 沙箱**里运行，工具变成 `await tools.xxx(...)` 的函数调用——循环、判断、批量处理全在代码里完成，**中间结果不进上下文，只有 return 的最终值进**。沙箱环境没有 Node、没有文件系统、没有网络。

这就是"四档工具披露"里 CodeModeOnly 档位的用途：工具多到一定程度，干脆让模型用代码编排。**"用代码替代多轮工具往返"这个方向，Trae 的 Code Mode 独立复刻了同一套，两大厂趋同。**

## 中途压缩（不打断回合）

Codex 的压缩是"常规操作"而不是"出事了救火"：

1. 软限触发：token 到 `auto_compact 上限 + 缓冲`，或窗口百分比到线；
2. **turn 中途就地压缩**：用一段固定的"交接摘要"prompt 总结历史 → 把初始上下文（用户指令、环境信息）重新注入到压缩摘要前面（保持和模型训练时一致的消息分布）→ 继续干活，**用户无感**；
3. 压缩范围有讲究：`BodyAfterPrefix` 只数新增部分，保护住已被缓存的提示词前缀（省钱）；
4. 压缩失败换模型重试。

工具输出也有硬规矩：默认 10000 token 截断，**保头保尾去中间**（开头有总述、结尾有结论，中间通常是废话）。

## 持久化与恢复

- 每个消息条目追加到 `~/.codex/sessions/日期/rollout-<时间戳>.jsonl`，支持恢复/回滚/截断；
- 记忆系统：`memory_summary.md` 注入每次对话 + memory 工具组（列表/读/搜/随手记），后台用独立的小模型做记忆抽取和固化。

## 值得我们抄的清单

| 抄什么 | 为什么 |
|--------|--------|
| 中途压缩 + 初始上下文重注入 | 把压缩从"降级路径"变成"常规控制流"，长任务不中断 |
| 工具输出截断：10k、保头尾 | 一行配置解决输出爆炸，数值可直接搬 |
| `get_context_remaining`（让模型自查剩余 token） | 模型知道预算才能自己规划节奏 |
| Code Mode 思想（不一定上 V8） | 多步搜索管线可以降级成"声明式 DSL"：fan-out + merge 两原语就够 |
| Stop hook 强制续跑 | 防"模型偷懒提前收工" |

## 别学的坑

- `core` crate 成了垃圾场（主循环/压缩/审批/沙箱/通话全在里面，单文件 2843 行）——模块要按职责切开；
- 同一工具能不能用要过五道开关的组合，测试靠海量用例硬扛——默认值要先设计好。
