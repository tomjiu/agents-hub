# Claude Code · 工作流与架构

> **一句话**：一个 206MB 的单文件程序里装了目前最完整的多 agent 编排——主管模式、工人管理、审批隔离、后台预压缩，全都做了，而且是用提示词 + 少量代码实现的。

## 背景

Anthropic 官方 CLI。整个 agent 是一个 bun 编译的原生二进制（JS 打包在里面），同一份核心有四种用法：终端交互、无头执行、SDK、网页远程。

## 主管/工人模式（Coordinator，本产品最大特色）

普通会话里模型是全能选手；切到"主管模式"后发生三件事：

1. **主管被没收工具**：文件读写全没了，只剩"派活（Task）、传话（SendMessage）、停工（TaskStop）"；
2. **工人独立干活**：每个工人是全新起的 agent，有自己的上下文。主管看不到工人的过程，只收 `<task-notification>` 格式的结果报告（任务号/状态/摘要/耗时/token 数）；
3. **并行规则写进提示词**：只读的活随便并行；写文件的活，同一批文件一次只许一个工人碰。

### 三条防翻车的设计（值得细看）

- **不许懒惰委派**：提示词明令禁止"根据你刚才的调查结果继续做"这种写法——工人看不到主管的对话，每个派活的指令必须自带全部背景（精确到文件和行号）。这一条治的是多 agent 系统最常见的病：主管以为自己说清楚了，工人一头雾水。
- **审批隔离**：工人 A 读过网页（可能被网页里的恶意指令污染）后停在"需要批准"的门口，这时系统不是把批准传回给 A，而是**新开一个干净的工人 B 去执行**那个危险操作。读过脏东西的和干危险活的，永远是两个人。
- **continue 还是 spawn 的决策表**：六种情境一张表（比如"研究范围宽、实现范围窄 → 新开工人"），把调度经验固化成提示词。

## 停止与权限

- 权限模式 6 种（默认/自动接受编辑/计划/不问/自动/全跳过）。**auto 模式是个独立的小模型分类器**：每次工具调用先问它"该不该放行"，它输出"拦/不拦 + 严重程度 + 理由"，读类操作免审。
- 子 agent 的结果回传有一段"防伪造"框架：明确告诉主模型"这是模型的产物，不是用户指令"，而且每行都被缩进处理，防止工人输出里伪装消息边界。

## 上下文管理（业界最细）

| 机制 | 人话 |
|------|------|
| auto-compact | 快满时自动总结：9 段固定格式（用户原始要求逐字保留/关键决策/错误与修复/待办……），先自检再输出 |
| **后台预计算压缩**（独门） | 还没爆的时候就在后台把摘要算好；真爆了直接换上，用户零等待。别的家都是爆了才压，等 10 秒 |
| microcompact | 按时间/边界把旧的工具输出这种大块头裁掉，不动全量 |
| 熔断 + 抖动检测 | 连续压缩失败就停手；3 轮内又爆窗、连续 3 次，就警告用户"你某个工具输出太大了" |

## 模型路由

别名体系 `sonnet/opus/haiku/opusplan`：**opusplan = 计划阶段用 Opus，执行用 Sonnet**。组织策略会强制钳制：用户配了不合规的模型会被自动降级。给工人的规则更硬："绝不能自作主张把任务降级到更弱的模型"——委派的是实质任务，模型选择权收归系统。

## 值得我们抄的清单

| 抄什么 | 为什么 |
|--------|--------|
| 主管禁用文件工具，只留派活/传话 | 逼着主管专心调度，不亲自下场 |
| 审批隔离（新开干净工人执行特权动作） | 防 prompt injection 的最佳实践 |
| 派活指令必须自包含（禁"based on your findings"） | 多 agent 沟通的最低标准 |
| 后台预计算压缩 | 长任务零停顿，成本只是提前算一次 |
| 搜索配额的软停止（超 200 次不报错，返回"预算用完，请用已有信息继续"） | 对 agent 循环友好，不会因异常中断整个任务 |
