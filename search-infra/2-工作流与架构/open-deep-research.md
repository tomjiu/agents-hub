# Open Deep Research · 工作流与架构

> **一句话**：LangChain 官方的深度研究 agent，全仓库核心只有 4 个 Python 文件，却把"研究型 agent 该怎么组织循环"写成了标准答案——尤其是**把'停止条件'做成一个工具调用**这一招。

## 背景

LangChain 开源项目，曾登上 Deep Research Bench 榜第 6。用 LangGraph（一种"流程图画出来、节点是函数"的框架）实现。代码极少（deep_researcher.py 719 行 + utils.py 926 行 + 提示词 + 配置），是四个研究向开源项目里最值得读源码的一个。

## 流程（一条线讲完）

```
1. 澄清（clarify_with_user）
   模型结构化判断"这个问题模糊吗"：模糊 → 反问用户一次；清楚 →
   强制输出一段"我理解了，将开始研究 XX"的复述（verification）再继续
2. 写研究简报（research brief）
   把所有对话压成一段简报。prompt 有五条硬规则，最关键的两条：
   "用户没说的维度，明确标'开放'，不许编造" + "按问题类型指定来源偏好"
3. 主管-研究员双层循环
   主管（supervisor）：把简报拆成研究任务 → 并行派发 → 收报告 → 决定继续还是结束
   研究员（researcher）：每个研究员领一个课题，自主搜网页+反思，
   干完把自己的工作压缩成一份带引用的报告
   —— 研究员之间完全隔离，互相看不到对方的工作
4. 终稿
   单次大模型调用：简报 + 全部研究员报告 → 最终报告
   主管的过程消息（调了什么工具、怎么想的）全部丢弃，只看素材
```

## 三个招牌设计

### 1. 停止条件三保险（最常被引用的一课）

| 保险 | 机制 |
|------|------|
| 显式 | 一个专门的 `ResearchComplete` 工具，模型调它 = "我确认研究完了"。可校验、可计数、可观测 |
| 隐式 | 模型如果连续输出里没有工具调用，也视为要结束 |
| 硬上限 | 主管最多 6 轮，每个研究员最多 10 次工具调用，各算各的，互不挤占 |

光靠"模型说完了"是靠不住的；光靠硬上限会浪费；三层叠加几乎不会失控。

### 2. think_tool（零成本的好设计）

一个**什么都不做的工具**：调用它只是把你写的反思原样记下来。配合 prompt 规则"每次搜索后必须单独调 think_tool，不许和其他工具并行"——在消息流里人为插入停顿点，逼模型"搜完先想一想再搜"。实测显著提高下一轮搜索决策质量，实现成本为零。

### 3. 压缩三层漏斗

```
第 1 层：URL 去重（多个搜索查询的结果合并，同 URL 保留第一次）
第 2 层：逐页摘要（便宜的小模型 gpt-4.1-mini 并行摘要每页，
         60 秒超时或失败 → 降级返回原文）
第 3 层：研究员级保真压缩（该研究员的全部工作 → 一份"逐字保留相关信息、
         禁止概括"的压缩报告 + 强制 Sources 清单）
```

主管收到的永远是压缩后的报告，所以同一个上下文装得下 5 个并行研究员的产出。

## 反面教材（同在这 4 个文件里）

1. **`or True` 吞错**：并行研究整体包了个 try/except，但条件写的是 `if is_token_limit_exceeded(...) or True:`——**所有异常一律当终止处理**，一次网络抖动烧掉整轮并行研究。（`or True` 让前面的 token 判断完全失效。）
2. **完全没有缓存**：同一 URL 在不同研究员之间、不同迭代之间重复搜索重复摘要，README 自曝 100 题评测花 $46-187。
3. **没有全局预算**：最坏情况 6×5×10=300 次 LLM 调用，没有任何总闸。
4. 引用完整性全靠 prompt 哀求（6 条 Guidelines 反复说"不许丢 source"），没有代码校验——编号错乱是真实风险。

## 值得我们抄的清单

| 抄什么 | 为什么 |
|--------|--------|
| ResearchComplete 显式停止工具 + 隐式兜底 + 双层硬上限 | 循环控制的直接模板（search-core v0.2 已抄） |
| think_tool 强制反思 | 零成本，一行工具注册 |
| 压缩漏斗（URL 去重 → 逐页摘要带超时降级 → 保真压缩） | 研究结果的 token 瘦身标准流程 |
| 澄清单次原则 + 不澄清也要复述确认 | 一次调用换来简报质量大涨 |
| 子图输出白名单（研究员只暴露 compressed_research 和 raw_notes） | 结构上保证中间过程不外泄 |
