# Open Deep Research · 搜索专题

> **一句话**：研究型搜索编排的教科书（代码只有 4 个文件）：三层压缩漏斗 + URL 去重 + 强制反思，把"多轮搜索不爆上下文"做成了标准流程——但它也示范了两个大坑：完全没缓存、`or True` 吞错。

## 搜索在它这里的定位

它不是搜索工具，是**用搜索做研究的 agent**。搜索后端刻意收敛到 3 个：Tavily（默认）、OpenAI/Anthropic 原生托管搜索、MCP（逃生舱，可接任意后端）。

为什么从 legacy 版的 9 个后端砍到 3 个？**支持矩阵越大，压缩管线越难统一**——每家的返回格式不同，第 2 层摘要就得为每家写适配。这个取舍值得记住：引擎多不如管线统一。

## 搜索链路四步（核心是第 3、4 步）

```
1. 多查询并发：一次工具调用可带多个 query（queries: List[str]），
   asyncio.gather 并发执行，include_raw_content 拿全文
   —— 一轮调用覆盖一个子主题的多个关键词组合，减少往返
2. URL 去重：多查询结果合并进 dict，key 是 URL，保留第一次出现的归属
3. 逐页摘要（第 1 层压缩）：便宜小模型（gpt-4.1-mini）并行摘要每页，
   结构化输出 {summary, key_excerpts}，每页压到原文 25-30%；
   60 秒超时或失败 → 降级返回原文（宁多勿缺）
4. 研究员级保真压缩（第 2 层）：该研究员全部工作 →
   "逐字保留相关信息、禁止概括"的压缩报告 + 强制 Sources 清单；
   超 token 重试 3 次，每次砍掉最近一轮上下文
```

## 预算与停止的 prompt 写法（直接可用的模板）

研究系统提示词里的行为约束：

- "简单 query 最多 2-3 次搜索，复杂最多 5 次"
- "连续 2 次搜到相似信息就停"
- 先宽泛搜索，反思后补窄查询

加上 think_tool（每轮搜索后强制单独反思一次，见工作流文件夹）——**预算+停止特征+反思节奏，三样都用 prompt 写死**，实测有效。

## legacy 版的遗产：embedding rerank（另一条路）

legacy 版有个没进新版的模块：网页切块（1500 字符、overlap 200）→ 内存向量库召回 top chunks → 按 URL 重拼 + sha256 去重。**比 LLM 摘要便宜且不丢细节，但实现复杂一个量级**——新版权衡后放弃。我们的 v0 用 Perplexica 式双阈值（更简单），长文档场景可以回头看这条。

## 反面教材（每一条都是真金白银的教训）

1. **`or True` 吞错**（deep_researcher.py:334）：并行研究的整体异常处理写的是 `if is_token_limit_exceeded(...) or True:` ——token 判断永远短路，所有异常一律终止全局。一次网络抖动 = 烧掉整轮 5 个并行研究员。
2. **零缓存**：URL 去重只在单次工具调用内部；跨迭代、跨研究员的重复搜索重复摘要照付。README 自曝 100 题评测 $46-187。
3. **无全局预算**：最坏 6×5×10 = 300 次 LLM 调用，没有总闸。
4. **引用无代码校验**：压缩 prompt 用 6 条 Guidelines 反复哀求"不许丢 source"——说明丢引用是真实高频问题，但没有任何代码层兜底。

## 值得我们抄的清单

| 抄什么 | 为什么 |
|--------|--------|
| 三层压缩漏斗（URL 去重 → 逐页摘要带 60s 降级 → 保真压缩） | 研究结果 token 瘦身的标准流程 |
| 一次调用多 query 并发 | 减少工具往返 |
| 预算+停止特征写进 prompt 的具体措辞 | 直接抄文案 |
| 逐页摘要超时降级返回原文 | 宁可多花 token 也不丢信息 |
| 后端收敛（3 个）换管线统一 | 引擎多不如管线统一 |
