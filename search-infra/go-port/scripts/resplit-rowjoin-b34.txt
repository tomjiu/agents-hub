== 机制A 长句二次切分 — 设计探针否决, 不 ship ==
探针实测(b34-design-probe.json, 12k 窗产品 fetch + b34SimResplit 逗号/分号/冒号/破折号
  切 clause 贪心打包 ≤300r + b32SentenceScore 产品评分镜像):
  1) libretexts(304r→4 长句): 答案段 "…decorated with guns fixed on a colourful Persian rug…"
     score=1.00 cover=0 过不了 minCover=2 — 且 b31 已裁决该案="Persia⊂Persian rug"假 D1:
     不翻恰是正确保护(交付假答案比不交付更差)。
  2) grokipedia(767r→12 长句): 答案段 "Garfunkel enrolled at Columbia University in 1958,
     initially pursuing architecture…" score=7.50 cover=3 入池, 但页面级竞争被榜单散文压死:
     "peaking at number 21 on the Billboard 200…" score=12.75 cover=1(数字/专名奖励密集)。
     rep-per-sentence + cover 准入收窄后仍败(同页 "Sound of Silence" 段 11.0 cover=3)。
     → B2a 实为 B1 竞争层残余(bonus 富集散文 vs 答案散文), 非门槛层可解;
       归入 b35+ "专名行竞争/奖励结构"家族(spartacus 型同族)。
  3) 洪泛风险: 重切向所有长句页注入 bonus 富集段 swarm, 现任健康 best 会被挤掉
     (grokipedia 现任best=bio intro ~3.x → 12.75 纯噪声上头), 活窗 REG 风险真实。
结论: 零增益(两案均不可达)+纯风险 → 否决。探针产物 answer_extract_b34_test.go +
  b34-design-probe.json 在档防再诉讼(候选被否决≠候选丢失, 记法进方法论 §18)。

== 机制B 表格感知行候选 — 收窄后实弹 ==
探针同时暴露朴素 run 成行的毒: grokipedia 页头 run "[35][31]·Solo Career Trajectory·
  Debut and Exploration (1970–1975)" score=5.25 会以 TOC 垃圾上头。
定稿 v2 = b19RowCandidates(answer_extract.go): 连续 cell-like 短行 run(≥2, <40r 无句末标点)
  → join " · " 贪心 chunk ≤300r → 行级准入两把尺(既有 lenOk/样板/评分闸之上):
  ① 数据表锚: run 含 ≥1 纯数字行(唱片年表/统计表年份列形态; 页头/TOC 无独立数字行)
  ② 行含 ≥1 查询词(反数字刷分, b33 样板句血统: cover=0 引用行/坐标行不入场)
  探针复验: grokipedia 4 行候选全排除 / libretexts 3 行候选全排除 / allmusic 型
  "1981·…·Atlantic / JDC Records" 存活(score≈7.0 险胜 prose)。
已知盲区: CJK 纯表格无独立数字行(评测语料 EN-only, 观察项)。
