批 29 证据: analyze-upstream-drift.mjs goldAt 大小写 bug (b24 引入) — 复现/根因/影响面/修正
=====================================================================================

【发现路径】
批 29 立项做"垃圾 gold 过滤"前例行对拍: 同一份 b29 新窗 dump 上, dump 内联 hitRank
(eval 口径, hay 先 toLowerCase) vs drift 工具 goldAt 重算, NQ 50/98 行分歧、TQA 69/100 行
分歧, 方向全部是"内联找到、goldAt 找不到"。逻辑上同字段同匹配器不可能分歧 → goldAt 实现
偏离了匹配器调用契约。

【根因】
matchEvidence(hay, answers) 内部只对 answers 做 toLowerCase, hay 侧小写是调用方契约:
  - eval-external.mjs:89        hays = refs.map(r => `${title}\n${snippet}`.toLowerCase())  ✓
  - eval-external-dump.mjs:84   同上                                                       ✓
  - analyze-suppression.mjs:65  matchEvidence(`${t}\n${s}`.toLowerCase(), ...)             ✓
  - analyze-rerank-replay.mjs:97 同上                                                      ✓
  - analyze-upstream-drift.mjs:45 (b24) matchEvidence(`${t}\n${s}`, ...) 直接传原串        ✗
后果: 大小写敏感匹配 — 专名型答案(China / Debra Winger / New Zealand / Richard Marx…)
在 title+snippet 里以大写形态出现时全部漏判; 只有纯小写/数字型答案(1990 等)能命中。
b24 提交信息声称"snippet 层 gold 判定与 eval 逐字一致"实为不等价 — 跨工具拷贝"看着一样"
不等于"跑起来一样", 必须金样本锁(b29 修法)。

【量化】
b22win 文件(journal 首行)上: b22 归因工具(小写正确) NQ miss=63 → hit@1≈35%;
drift 工具(坏) gold@1=13.3% — 同一文件差 2.7 倍。b29 新窗修正后(对照):
  NQ:  坏口径 gold@1/@10/@20 = 12.2% / 29.6% / 32.7%  →  修好 = 38.8% / 77.6% / 82.7%
  TQA: 坏口径 = 15.0% / 31.0% / 37.0%                →  修好 = 57.0% / 91.0% / 94.0%
修正后 goldAt(20) 与 dump 内联 hitRank 对拍: NQ 98/98, TQA 100/100, 0 分歧。

【b24 结论影响面复审】

  - rank1 换页率 33.7%/30.0% (URL 对比)
  - 引擎腿出现率/腿数均值/墙钟 (engines 字段)
  - 锚窗 journal 机制本身(--journal-only 单窗入档为 b29 补齐)

    "融合层头部对腿换血免疫"的实证引用(该命题回到待验证状态);

    未来同案可机器归因)。
