# 批 26: cross-encoder 离线重放 — 神经重排挂账最终裁决 (2026-09-06)

## 一、实验设置

- 数据: b25 窗 dump (NQ 98 + TQA 100, refs top-20 引擎层 snippet), 零上游查询成本。
- 模型: Xenova/ms-marco-MiniLM-L-6-v2 ONNX quantized (22MB, 6 层 MiniLM, ms-marco 相关性训练),
  tokenizers + onnxruntime 推理 (无 PyTorch 依赖), CPUExecutionProvider。
- 打分对象: query × (title+snippet), 与评测判定 hay 同源; top-10 池 (主线) / top-20 池 (副线)。
- 变体: base (融合原序) / cross (纯重排) / rrf (K=60 融合) / lin-λ (score*10 + λ·cs 增量式, λ∈{1,2,4})。
- 判定: verbatim+tokenAND 与 eval-external.mjs 逐字一致; 脚本 scripts/ce-rerank-replay.py 入仓。

## 二、核心结果 (合并 198 题, dump 层口径)

| 变体 | pool | hit@1 | hit@3 |
|------|------|-------|-------|
| base | p10 | 94/198 = 47.5% | 65.2% |
| **cross** | p10 | **128/198 = 64.6% (+17.1)** | **77.3% (+12.1)** |
| rrf | p10 | 58.6% (+11.1) | 75.3% |
| lin-4 | p10 | 64.6% (+17.1) | 76.8% |
| cross | p20 | 64.1% (+16.6) | 77.3% |
| **lin-4** | p20 | **130/198 = 65.7% (+18.2)** | 77.3% |

- **双集同向大幅正向**: NQ 36.7→56.1 (+19.4pp), TQA 58.0→73.0 (+15.0pp)。b20 的"双集同向才立项"
  判据首次以最大幅度通过。
- **位次保持池 (dump gold@2-10, n=71) cross 救回 43/71 = 60.6%, 掉出 0**。A 型假设
  (rank1 相关但无直接答案, gold Q&A 页直接含答案) 完全验证: Stagecoach (Milestone 人物页压
  博物馆页), "next PM after Balfour" (前任 Salisbury 压列表页), Matthau (人物页压 The
  Kentuckian 页), Balfour, Europe 百分比, 地铁题 (Q&A 逐字匹配页) 全部救回。
- **损伤面 flip 9/94 = 9.6%**: 全部跌位 2-4 (无一跌出 top-10, 无一变 miss)。逐条定性:
  真损伤 3-4 题 (Rich Man 同名歌歧义 / Till Death Us Do Part 问题串假亲和 / Brezhnev 列表页
  语义误导), 其余为"语义合理但词面不匹配评测 matcher"的口径税 (River Phoenix 最后电影新闻页
  语义更直接但 snippet 无片名 token, Gomez 角色页比剧集页更相关)。
- **净账: hit@1 +34 题 (+17.1pp), hit@3 +24 题 (+12.1pp)** — b19 以来最大单杠杆, 一个数量级
  高于 b23 注入修复 (+4.2pp 同窗)。
- **变体选择: lin-4 (score*10 + 4·cs 增量式) p20 最高 65.7%** — 增量式保住融合分基底
  (b20 方法论复用), 损伤面比纯 cross 更可控 (融合分韧性 + cross 增量), 首选产品变体。

## 三、成本实测 (b20 预估对照)

| 项 | b20 预估 | b26 实测 |
|----|---------|---------|
| 模型文件 | 100MB-1GB | **22MB** (quantized ONNX) |
| runtime | "runtime 依赖" | tokenizers+onnxruntime, **无 PyTorch** |
| 延迟 | CPU 100-300ms | **139-153ms/题** (batch top-10, 单线程 CPU) |
| 并行空间 | 与 b19 抓正文并行净 ~0-100ms | 成立 (重排在融合层后, 注入层抓正文窗口天然并行) |

## 四、裁决: 触发条件实质击发, b20 结论修订

- b20 说"不上"的三理由在新数据下: ①"零模型实测吃不动"→ 仍成立但**外推错误** — TF-hash 词面
  模型无效 ≠ 语义模型无效; ②"miss 大半非排序问题"→ b25 已证位次保持 61.8% of miss@1 就是
  排序问题; ③"成本结构不匹配"→ 22MB/无 PyTorch/140ms 可并行, 成本结构已被 quantized ONNX
  路线重写。
- **语义压顶挂账触发条件① (广义口径) 实质击发**: 广义压顶 61.8% >> 15% 线, 且 cross-encoder
  对该池实测救回 60.6%、净 hit@1 +17.1pp、双集同向。
- **批 27 立项: 产品集成** — Go 侧集成路线 (onnxruntime_go binding 或 python sidecar),
  SC_RERANK 开关, 重排位置=融合层后/注入层前 (title+snippet 打分, 与重放口径一致),
  变体首选 lin-4 增量式, 同窗 A/B 全量验证 (SC_RERANK 0/1 对拍) + bench 延迟门禁。

## 五、方法论沉淀

- **离线重放的三段式**: dump 落盘 (零上游成本) → 结构归因 (b25 找到目标池) → 模型重放 (b26
  实测可救率)。挂账决策从"词面直觉"升级为"目标池 + 模型实测"。
- **损伤面必须逐条定性**: flip 9 题里"评测口径税"与"真损伤"要分开 — 前者是 matcher 与语义
  模型的口径差 (产品语义上可能还是改进), 后者才是重排的真实 tax。
- **渲染脚本防 for 变量泄漏**: Python for 循环变量泄漏到后续循环导致渲染指向错误对象
  (Kitchen Brigade 幽灵页), 捕获到元组内解决; 判定逻辑与渲染逻辑要分开验证 (flip 判定对,
  渲染错, 若只看渲染会误杀整个实验)。
- **限制声明**: 重放口径是引擎层 snippet (title+snippet), 产品集成后重排对象相同 (融合层后
  注入层前), 口径一致; 但 dump 与 align eval 两次跑隔 30-60min 存在窗口漂移成分 (b24: rank1
  换页率 30-34%), 结构性结论 (池级救回率/双集同向) 不受影响。
