# Codex · 技能与工具市场

> **一句话**：OpenAI 的 Codex 用了和 Claude Code 同一套 SKILL.md 标准，但它的特色是把"工具怎么暴露给模型"做成了**四档开关**——工具再多也不会撑爆上下文，这是所有产品里最系统化的答案。

## 背景

OpenAI 官方终端 agent，开源（Rust，约 100 个 crate）。因为开源，这次的证据是直接读源码，比拆闭源的可靠得多。仓库里甚至带着官方自己的 `.codex/skills/` 真实技能文件（`analysis/codex/source/.codex/skills/`，有 code-review、babysit-pr 等十几个），可以直接当标本看。

## 技能系统

技能 = `SKILL.md` + 开头写名字/描述/依赖。安装在四层目录，优先级从高到低：

```
用户级 ~/.codex/  >  仓库级 <repo>/  >  系统级  >  管理员级
```

运作方式是典型的渐进披露：

1. 每轮只把**技能目录**（名字 + 描述 + 位置）渲染进提示词；
2. 用户提到 `$技能名`、或任务匹配描述时，才把 SKILL.md 全文注入本轮；
3. 全文读完还不够，再按技能里的引用去读 `references/` 目录下的补充材料。

另一个独立的系统是 **AGENTS.md**（项目说明文件）：从项目根一路拼接到当前目录，每层都可被 `AGENTS.override.md` 覆盖，总量有字节预算、超了逐文件截断。这解决的是"大仓库里不同子目录有不同规矩"的问题。

## 工具四档披露（本产品最有价值的发明）

工具不是"有就全给模型看"，而是按四档管理：

| 档位 | 模型能看到什么 | 什么时候用 |
|------|---------------|-----------|
| **Direct（明牌）** | 完整定义直接进提示词 | 常用核心工具 |
| **Deferred（暗牌）** | 只有元数据，模型用 `tool_search` 搜到才加载 | MCP 插的工具一多就用这档 |
| **CodeModeOnly（代码模式专用）** | 只在代码执行环境里可见 | 最新的模型直接写 JS 批量编排工具时用 |
| **Hidden（隐藏）** | 完全不可见 | 内部工具 |

暗牌工具怎么找回来？Codex 用 **BM25 搜索**（一种经典的文本检索算法）给所有暗牌工具的"名字+描述+参数说明"建索引，模型用 `tool_search` 查询，命中后工具定义动态加载进会话。索引是惰性重建的（工具表变了才重建），工程上很省。

和 Claude Code 的手写打分对比：Codex 的 BM25 不用人工调权重，工具多了更稳。**两家独立演化出了同一个方向，验证了"按需加载"是正确答案。**

## 插件与市场

插件 = 技能 + MCP 服务器 + 工具的打包体。有官方 marketplace 源，配套一个 `tool_suggest` 机制（检测到任务需要某个插件时推荐安装）。技能还可以声明 MCP 依赖——第一次使用时自动弹安装流程。

## 值得我们抄的清单

| 抄什么 | 为什么 |
|--------|--------|
| 四档披露模型（Direct/Deferred/CodeModeOnly/Hidden） | 比二元的"显示/隐藏"细得多，是工具数量增长的完整路线图 |
| BM25 tool_search + 惰性重建索引 | 零人工调参，实现就几十行 |
| AGENTS.md 根→目录逐级拼接 + override + 字节预算 | 用户自定义偏好的最佳载体 |
| 技能目录先行、全文按需注入 | 省 token 的标准姿势 |

## 别学的坑

- 同一个工具能不能出现，要过五道门（feature 开关 × 模型元数据 × 沙箱配置……），组合爆炸导致测试难写——先设计好默认值，别让每个工具都过五关。
