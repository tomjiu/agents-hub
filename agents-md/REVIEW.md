主要交付：[共用基础模板](base/AGENTS.md)。模板为独立完整文本，共九部分，新增独立的环境卫生与资源回收章节。

补充参考已读的两篇本仓研究：[07 · 提示工程与量化分析](research/agents-md-audit/analysis/07-提示工程与量化分析.md)、[08 · 业界惯例对照](research/agents-md-audit/analysis/08-业界惯例对照.md)。本版采用条件式规则、明确的验证状态、行为规范与项目事实分层，并补充外来材料指令的审查和宿主权限边界。这些是设计参考，不等于本次已实测模型遵循率；不将短句、首尾位置或固定枚举表述为行为正确的保证。

## 建议的拼接边界

维护时：共用基础模板 + 可选片段 + 项目类型规则 + 项目专属规则。
使用时：生成一个完整的项目 AGENTS.md，保留版本与来源标记。

基础模板已覆盖九类工程纪律，后续 fragments 只增加专项规则，不将同一句规则再次拼入。顺序应由显式配置决定，而不是依赖文件枚举顺序。

## 项目专属部分建议骨架

1. 项目目标与真实入口：产品、服务、库的边界；权威架构文档。
2. 目录与维护源：手写内容、派生文件、生成命令、禁止误清理的资产。
3. 环境与依赖：版本、操作系统、运行时位置及必要前置条件。
4. 验证映射：改动范围 → 检查命令 → 能证明什么 → 环境限制。
5. 协作与交付：远端、分支、PR、审核、合并和发布权限。
6. 项目特有限制：明确适用范围、原因与替代流程。

## 本版有意不继承的绝对化写法

- 不把某项目“禁止本地构建”或“必须本地验证、没有 CI”提升为全局规则。
- 不要求每项工作必开 issue、每次提交立刻推送，也不授权自动发布或扩展任务。
- 不将固定时间、测试数量、旧平台状态或具体机器路径写入共用规范。
- 不把依赖锁文件视为必须删除的运行时垃圾。
- 不以文件大小判断规范是否优质，不把代码块内的井号注释误判为标题。
- 不把同邮箱直接认定为同一平台账户；不把未验证的 token 当作可用凭据。

## 0.3.0 公开对照后的落实

依据与限制见 [公开实现对照](PUBLIC-COMPARISON.md)。本轮未重新查询上游版本。

- 基础模板补入依赖/生成物同步、取消与生命周期释放、缺陷复现、有效验证结果复用、对外内容审查、拼接冲突处理和机制性保障。
- 纠正“模拟仅限单元测试”：允许标明范围的测试替身、合成数据及沙箱，但不能冒充真实端到端验证。
- 新增 [项目专属模板](templates/project.md)，要求填入实际工具版本、工作目录、可执行命令、前置条件、功能验收清单、备份关系及清理边界。占位项尚未验证，不是已部署配置。
- 新增 [UI 验收片段](fragments/ui-acceptance.md)，补充键盘、焦点、可访问名称、多状态、窗口适配和重复提交验证。
- 拼接方式为基础正文 + 已选片段正文 + 填写后的项目正文。基础 compose 命令已实现并通过隔离用例；语义冲突检测和项目规则客户端集成验证尚未完成。
- 未替换 mdcore、ai-bid-research、kokoa 或 moontranslator 的现有规则。

## 审阅重点

这版偏向“可执行的工程纪律”，压缩了长事故叙述但保留其防错方法。采用条件触发，避免每项小任务都做全套重流程；完整项目交付仍需要全功能验收。

项目部分还需配置实际命令、受管资源与不能清理的资产、编译缓存预算、远端/备份关系、CI 触发策略及功能验收入口。模板本身不代替这些项目事实，也不意味着本次已经推送、清缓存或点击测试了某个产品。

请重点看规则是否过严、哪些条目值得常驻、哪些应下放到可选片段。现有项目的定制内容没有删改。
